## 一、一页决策摘要

做四件事，按这个顺序：

| 序 | 做什么 | 为什么 | 涉及 |
| --- | --- | --- | --- |
| P0 | 加"帧参数与缓存版本"骨架 | 后面所有改动都要靠它回滚 | `WidgetFrames.kt`、`WidgetTicker.kt` |
| P1 | 换渲染内核：GLSL 离屏烘焙（液体/雾/光/景深/颗粒） | 现在 Canvas 2D 的"渐变+贴纸粒子"是廉价感的根 | 新增 `widget/shader/*` |
| P2 | 帧管线换代：40 帧 / 200ms / 8s 闭合 / 准闭合长叠化 / 总像素 ≤ 520 万 | 现在的 24 帧 250ms + 200ms 叠化 = 幻灯片感 | `WidgetFrames.kt`、24 个 `layout/widget_today_f_*.xml` |
| P3 | 画面内容换代：24~30 款"缓流 / 光晕 / 静图微动" | 低帧率只有低频大形能骗过眼睛 | 服务端 catalog + 素材 |
| P4 | 信息层：等宽数字、8pt 栅格、玻璃层、按帧取色、天气/时段联动 | 小组件的"贵感"一半来自排版，不是背景 | `TodayWidgetProvider.kt`、24 个 layout |

App 内主题（`DynamicBackground`）同一套内核、同一份素材，**但走实时 GL 60fps**，不再和小部件抢同一条"预渲染"的路 —— 见 `03_App主题改造方案.md`。

**一条必须接受的现实**：`RemoteViews` 在框架层面不存在 60fps（帧要经 `setImageViewUri` 交给桌面进程解码重绘，桌面自己还会节流）。因此"像 wallpaper 一样"只能落在两件事上：**画面质感**（可以做到壁纸级）和**感知流畅度**（靠运动幅度、闭合、叠化骗过眼睛，不是靠帧率）。任何"把帧率提到 30fps"的方案都是错的，别做。

## 四、红线（越了就是返工）

1. **不许提高桌面帧率**：`flipInterval` 只能落在 180~450ms 区间。低于 180ms 在国产 ROM 的 launcher 上会被节流或直接丢弃动画，表现比现在更差。
2. **不许把视频/GIF 直接塞进小组件**：解码 + 耗电 + 掉帧，且 `RemoteViews` 里没有可靠的视频播放路径。视频只允许出现在"烘焙源"里（先抽帧，再进管线）。
3. **不许直搬 Shadertoy**：默认 CC BY-NC-SA 3.0，禁商用，且要求同协议。学会思路、自己重写。
4. **不许用 Wallpaper Engine 创意工坊素材**：Steam 订阅协议限定在 Steam 客户端内使用，不能随 APK 分发。
5. **不许把 `DynPainter` 删掉或改签名**：App 与小部件都在调用它，它是回退路径。新内核并行存在。
6. **不许在广播/主线程做烘焙**：单帧 40 万像素的烘焙曾经就是"App 明显卡顿"的元凶（见 `WidgetFrames.ensureAsync` 注释）。所有烘焙走后台线程 + 落盘缓存。
7. **不许省略"版本号进缓存 key"**：换了内核不升级缓存版本，用户会一直看到旧帧（`existingFiles` 靠 `meta` 里的 stamp 比对，stamp 里没有内核版本）。
