# 02 · 桌面小组件改造方案（重点）

> 本文是整套方案的主文件。所有结论都对着仓库现有代码写，动手前先读这几个文件：
> `widget/WidgetFrames.kt`、`widget/TodayWidgetProvider.kt`、`widget/WidgetTicker.kt`、`widget/DynPainter.kt`、`widget/ArtLibrary.kt`、`res/layout/widget_today.xml`。

---

## 1. 诊断：现在为什么"像幻灯片"而不是"像壁纸"

四条根因，按影响从大到小：

**① 画面构成是"渐变底 + 贴纸粒子"。**
`DynPainter` 的做法是：一张竖向渐变底图（`fillVertical`，缓存 1/4 分辨率）+ 若干 `glow()` 光团 + 一批随机粒子（`PETALS`/`SNOW`/`RAIN`/`MATRIX`）。这套画法在 60fps 下勉强能看，在 4fps 下必然崩——因为**粒子是高频小元素**，低帧率下它们只会"瞬移"。真正能撑住低帧率的只有低频大形：雾、液态、光晕、色场。

**② 空间层次是单一的。**
所有元素画在同一焦平面上。Wallpaper Engine 那类壁纸之所以"高级"，在于**景深**：前景虚、中景清、背景极虚，还有光溢出（bloom）和暗角。没有这四样，画面就是"平的"。

**③ 时间结构是"全屏同步 + 短循环 + 长叠化"。**
`FRAMES=24 × STEP_SEC=0.25 = 6.0s` 循环，`flipInterval=250ms`，交叉淡入 **200ms**。
- 200ms 淡入 / 250ms 间隔 = **80% 的时间都在双重曝光**。任何有硬边的元素都会抖成双影。
- 6 秒循环，人眼两三个循环就认出重复 → "这是段循环动画"的廉价感。

**④ 帧预算花在了错的地方。**
每帧 26 万像素（≈733×355）——为了"清晰"。但背景里没有文字（文字是独立 `TextView`），柔焦背景放大 1.5~2 倍根本看不出来。**这些像素应该换成帧数和循环长度。**

## 2. 目标画面形态（先定标准，再写代码）

一套合格的"壁纸级"静态帧，必须同时具备这五样，缺一样就是廉价感：

| 要素 | 具体要求 | 检查方法 |
| --- | --- | --- |
| 层次 | ≥3 个焦平面，前景模糊半径 ≥ 背景的 3 倍 | 缩到 25% 看，还能分出前后 |
| 光溢出 | 亮部周围有柔和辉光，不是硬边亮块 | 亮部边缘 3~5px 内有渐变衰减 |
| 暗角 | 四角压暗 8~14%，中心不被压 | 取四角/中心亮度比 |
| 颗粒 | 1.5~2.5% 强度的静态噪点（screen 空间，不随帧变） | 放大 200% 看有细颗粒，无条带 |
| 无 banding | 8-bit 输出必须抖动（Bayer 4×4 或三角噪声 1/2 LSB） | 深色渐变区放大看没有色阶台阶 |

**唯一豁免**：`grain` 必须在 screen 空间固定（同一套主题每帧噪点位置相同）。否则 5fps 下噪点会"闪"，比没有更糟。

## 3. 帧管线（数值与数学）

### 3.1 参数

| 参数 | 日常款 | 招牌款（≤3 款） | 依据 |
| --- | --- | --- | --- |
| `FRAMES` | 40 | 24 | 40 帧让单帧位移小到看不出步进 |
| `STEP_SEC` | 0.20 | 0.40 | 循环 8.0s / 9.6s |
| 单帧像素 | ≤13 万（≈480×270 于 16:9） | ≤26 万（≈680×380） | 总像素 520 万 / 630 万 |
| `flipInterval` | 200ms | 400ms | 只允许 180~450ms |
| 交叉淡入 | 110ms `decelerate` | 200ms `decelerate` | 叠化占比 55% / 50%，比现状的 80% 低一档 |

### 3.2 闭合数学（照抄这个条件，不要自创）

设循环 `T = FRAMES × STEP_SEC`。内核里任何一层元素的相位必须是：

```
phase_i(t) = 2π × ( k_i × t / T + φ_i )      k_i ∈ 整数, φ_i ∈ [0,1)
```

`k_i` 取整数 → 帧 N-1 接帧 0 时相位差恰好是 `2π × k_i`，**严格闭合**，无需额外处理。

**感知上"看不出循环"靠三件事，不靠加长 T：**

1. `k_i` 取值分散且互不成简单倍频：背景层 `k=1`，中景流体 `k=2`、`k=3`，前景光斑 `k=5`，涟漪 `k=7`。整幅画面的重复周期仍是 T，但**没有任何两个元素同时回到起点之后又同时离开**，眼睛抓不到"整帧重现"的锚点。
2. 位移幅度与 `k` 成反比：`k=7` 的那一层位移只有 `k=1` 的 1/5，看起来是"抖动"而非"循环"。
3. **循环内闭合 + 循环间变化由真实世界驱动**：整体色温/亮度按本地时间（早/午/晚/夜四档）与天气偏移，每 30 分钟或天气变化时重新烘焙。这样"每天看到的不一样"是真的不一样，不靠打破闭合去伪造。

**准闭合（仅用于招牌款，可选）**：若某一层用非整数 `k`（如 `k=2.5`）以获得更"自然"的运动，衔接处相位漂移半周期，此时必须把衔接那一次的叠化临时加长到 300ms 掩盖。**只有明确写注释、且只在招牌款用，日常款一律严格闭合。**

### 3.3 位移预算（防"步进感"的硬规则）

任一可见元素在 200ms 内的位移，**不得超过它自身特征尺寸的 1/3**。

计算方式：元素总行程 `S`，循环内来回 `k` 次 → 单帧位移 = `2·S·k / FRAMES`。举例：雾带横向行程 3% 屏宽、`k=2`、40 帧 → 单帧 0.3% 屏宽，肉眼完全看不出步进。反过来，若某元素单帧位移达到 2% 屏宽（如雪花下落），它在 5fps 下就是"瞬移"——**这类元素不许进小组件库**。

判定表（把现有 15 款按这个筛）：

| 现有款 | 判定 | 处置 |
| --- | --- | --- |
| `SILK` `DUSK` `BREATHE` `AURORA`(降速后) `NEBULA`(降速后) `BOKEH`(降速后) | 低频大形 | 保留思路，用新内核重画 |
| `PETALS` `SNOW` `RAIN` `MATRIX` `BUBBLES` `STARS`(星点闪烁) | 高频小元素 | **不进小组件库**；只保留在 App 内 60fps 与动态壁纸 |
| `RIPPLES` `WAVES` `FIREFLIES` | 边缘情况 | 降速 + 加大特征尺寸后可进，需逐帧验收 |

### 3.4 预算与落盘

- 帧文件：`cacheDir/wframes2/<presetKey>/f{N}.png` + `meta.json`。**目录从 `wframes` 改名为 `wframes2`**，避免读到旧内核的帧。
- `meta.json` 字段（替代现在那行字符串 stamp）：

```json
{
  "kernel": "gl2",
  "spec": "shader:liquid:ffa06bff",
  "w": 960, "h": 520, "speed": 1.0,
  "frames": 40, "step": 0.2,
  "built": 1750000000,
  "shaderHash": "a1b2c3d4"
}
```

`existingFiles()` 必须核对 `kernel`、`spec`、`w`、`h`、`frames`、`step`、`shaderHash` 六项，任一项不符即判失效重烘焙。**现在的 `stamp()` 里没有内核版本、也没有帧数，这两个必须加**，否则换代后用户永远看到旧帧、或者 24 帧目录被当成 40 帧读取（后半段全是空文件）。

- 压缩：API ≥30 用 `Bitmap.CompressFormat.WEBP_LOSSLESS`（带 alpha，比 PNG 小 25~35%）；API 26~29 回退 PNG。**不要用 JPEG**——圆角是透明的，会被填黑（这是 3.2.1 修过的坑）。

### 3.5 渐进式烘焙（体验关键）

一次烘焙 40 帧 × 40 万像素在低端机上要 6~10s，用户切主题后干等是不行的。

1. 切换瞬间：用**已缓存的同款 8 帧粗糙版**（或上一主题的首帧）先上桌，同时显示"正在生成"角标（`widget_flip` 旁边一个 `TextView`，2.5s 后自动隐藏）。
2. 后台线程按 `FRAMES` 均匀烘焙，**每完成 8 帧**就整目录原子替换一次（写 `meta.json.tmp` → rename），桌面最多看到 2 次跳变。
3. 全套完成 → 写最终 `meta.json` → `AppWidgetManager.notifyAppWidgetViewDataChanged` / 重新 `updateAppWidget` 触发一次刷新。

## 4. 渲染内核

### 4.1 架构

```
ui.theme / widget
   ↓ 参数（preset + accent + 时间档 + 天气档）
ShaderStudio (新增 widget/shader/ShaderStudio.kt)
   ↓ EGL pbuffer, GLES 3.0 离屏
GlProgram (新增 widget/shader/GlProgram.kt)   ← 编译/缓存/失败自检
   ↓ 4 个 pass
ShaderPreset (新增 widget/shader/ShaderPresets.kt) ← 每款主题 = 一段 GLSL + 一组 uniform
   ↓ Bitmap (RGBA8)
WidgetFrames (改) → 圆角 → WebP/PNG 落盘 → 桌面 ViewFlipper
```

**为什么保留两条内核并行**：`DynPainter` 是 15 款老主题 + 动态壁纸 + App 旧路径的实现，GL 在某些国产 ROM 上会失败（见 §8）。新内核只服务新图库，老款继续走老路。

### 4.2 Pass 设计（烘焙时不在乎实时性，可以多 pass 换质量）

| pass | 内容 | 分辨率 |
| --- | --- | --- |
| P1 `base` | 底色 + 大尺度色场 + 主光位置 | 1× |
| P2 `warp` | domain-warp 的 fbm 驱动流体/雾/液态；`k` 由 uniform 传 | 1× |
| P3 `blur` | 双层焦外：`fgBlur`（半径 8~14px）与 `bgBlur`（2~4px） | 0.5× 降采样后再升采样 |
| P4 `composite` | bloom（亮部阈值提取 + 3 级降采样模糊叠加）+ filmic 色调映射 + 暗角 + 色差 0.3px + 静态颗粒 + 抖动 | 1× |

### 4.3 参考着色器骨架（P2+P4 合并的简版，可直接作为起点）

```glsl
#version 300 es
precision highp float;
out vec4 fragColor;
uniform vec2  uRes;
uniform float uT;        // 秒，来自 bake 的帧序：i * step
uniform float uT0;       // 循环长度 T，所有相位必须用它做模
uniform int   uK;        // 该层循环次数（整数！）
uniform vec3  uTint;     // 强调色（线性空间）
uniform vec3  uBase;     // 底色
uniform float uGrain;    // 1.5% ~ 2.5%
uniform float uVignette; // 0.08 ~ 0.14

float hash(vec2 p){ return fract(sin(dot(p, vec2(127.1,311.7))) * 43758.5453); }

float noise(vec2 p){
    vec2 i = floor(p), f = fract(p);
    vec2 u = f*f*(3.0-2.0*f);
    return mix(mix(hash(i), hash(i+vec2(1,0)), u.x),
               mix(hash(i+vec2(0,1)), hash(i+vec2(1,1)), u.x), u.y);
}

float fbm(vec2 p){
    float v = 0.0, a = 0.5;
    for (int i = 0; i < 5; i++){ v += a * noise(p); p *= 2.03; a *= 0.5; }
    return v;
}

// 相位严格闭合：2π * (k * t/T + off)，k 必须是整数
float phase(float off){ return 6.2831853 * (float(uK) * uT / uT0 + off); }

void main(){
    vec2 uv = gl_FragCoord.xy / uRes;

    // —— 双向 domain warp：这是"液态/雾"质感的来源
    vec2 q = uv * 3.0;
    float t = phase(0.0);
    vec2 warp = vec2(fbm(q + vec2(0.0, t*0.15)), fbm(q + vec2(5.2, -t*0.12)));
    float f = fbm(q + 2.2 * warp);

    // —— 底色 → 流体 → 高光，三段映射（别用纯 mix，要有层次）
    vec3 col = mix(uBase, uTint * 0.55 + uBase, smoothstep(0.25, 0.75, f));
    col += uTint * pow(f, 3.0) * 0.35;             // 高光溢出感

    // —— 暗角
    vec2 d = uv - 0.5;
    col *= 1.0 - uVignette * dot(d, d) * 2.0;

    // —— filmic 近似（压高光，避免死白）
    col = (col * (2.51 * col + 0.03)) / (col * (2.43 * col + 0.59) + 0.14);

    // —— 静态颗粒（screen 空间固定，不随帧变！）
    float g = hash(gl_FragCoord.xy) - 0.5;
    col += g * uGrain;

    // —— 8bit 抖动：不做这一步，深色渐变必有 banding
    float bayer = fract(dot(gl_FragCoord.xy, vec2(0.7548776662, 0.5698402910)));
    col += (bayer - 0.5) / 255.0;

    fragColor = vec4(clamp(col, 0.0, 1.0), 1.0);
}
```

要点（写错就白做）：
- `uK` 必须是 **int**，且 `uT0` 传的是整套循环长度，绝不写死 6.0。
- 颗粒用 `gl_FragCoord` 落在 screen 空间，**同一套主题每帧噪点位置必须一致**。
- 别在 `sRGB` 空间直接做加法混色，会发灰；要么在线性空间算完再转，要么接受近似但保证对比度。
- 只有 5 个 octave 就够，多了烘焙时间线性增长。

## 5. 信息层（决定"贵不贵"的另一半）

背景到位之后，卡片上的字如果还是"日期挤在左上角 24sp"，照样廉价。

### 5.1 排版规格

| 元素 | 规格 |
| --- | --- |
| 日期（"20"） | 44sp / w600 / **tabular figures（等宽数字）** / 行高 1.0 |
| 月份+星期 | 13sp / letterSpacing 0.12em / 全部大写或中文小字 |
| 温度/课次等次级信息 | 15sp / 不透明度 72% |
| 边距 | 外 20dp，元素间距 8dp 栅格 |
| 对齐 | 左基线对齐，右侧状态点单独一列，不撑满 |

**tabular figures 是硬要求**：不开启的话，时间从 `9:41` 跳到 `9:42`、温度从 `11°` 跳到 `12°` 时整行会左右抖一下，一天几十次，比任何动效都毁质感。实现：`Paint.setFontFeatureSettings("tnum")`（API 21+）或字体本身带 `tnum` 特性。

### 5.2 玻璃层（零运行时成本的做法）

不要在运行时做实时模糊（`RemoteViews` 做不到）。**烘焙时就把 scrim 画进帧里**：

- 帧底部 30% 高度叠一层从 `#00000000` 到 `#0000002E` 的线性渐变；
- 文字区域中心再叠一层极淡的中心光（`#FFFFFF0A`，半径 = 卡片宽 40%），模拟"玻璃高光"。

这样文字永远可读，且不需要额外的 `View` 或 `Drawable`。

### 5.3 取色

从烘焙好的首帧取三处采样（左上 1/8、中心、右下 7/8），平均后转 HSL：

- `L > 0.55` → 用深色字族（`#1A1626` / 65% 不透明）；
- 否则用现有亮色字族（`WidgetTheme.headColor` 等）。

这套逻辑 `Theme.kt` 里已有近似实现（`rememberPhotoExtremes`），抽成工具函数复用，**不要复制第三份**。

### 5.4 真实世界联动（这是"别人抄不走"的部分）

| 输入 | 效果 | 实现要点 |
| --- | --- | --- |
| 本地时间四档（早/午/晚/夜） | 色温偏移 + 亮度 ±8% | 每 30 分钟一个 alarm 重烘焙（命中缓存则只换 meta，不重画） |
| 天气（若 App 已有天气数据） | 雨天加低频雨幕层，雪天换冷色，晴天抬高对比 | **只在已有数据时联动，不许为此新增网络请求** |
| 电量/充电 | 充电时光晕呼吸幅度 +30% | 复用现有 `ACTION_BATTERY_CHANGED` 广播 |

## 7. 兼容与降级

| 场景 | 行为 |
| --- | --- |
| GLES3 不支持 / pbuffer 创建失败 | 开机自检（32×32 试渲染一次）写 `shader_ok=false`，图库里 shader 款置灰并提示"此设备仅支持经典动态主题"，自动回退 `DynPainter` 款 |
| program 编译失败 | 捕获编译日志，`fallback` 到同色系的 `DynPainter.Kind.DUSK`，记一次 `Log.w`，**不许崩溃** |
| 老 spec（`anim:aurora:ffa06bff`） | 继续解析；映射表：`aurora→shader:aurora`、`silk→shader:liquid`、`dusk→shader:dusk`…（映射表写在 `WidgetTheme.kt`，带注释说明"老用户不动"） |
| 用户已选但该款已下架 | 保留本地帧继续用，图库里标"已下架"，不强制切换 |
| 低端机发热 | 烘焙线程优先级 `THREAD_PRIORITY_BACKGROUND`，且一次只烘一套；连续两套未完成时取消前一个任务 |

## 8. 性能与耗电

| 环节 | 预算 | 手段 |
| --- | --- | --- |
| 烘焙（40 帧） | ≤ 8s，峰值内存 ≤ 60MB | 逐帧 `Bitmap` 落盘后立即 `recycle()`，不整批留在内存（现有 `render()` 返回 `List<Bitmap>` 的做法在 40 帧 × 40 万像素下会到 64MB，**必须改成流式**） |
| 首帧上桌 | ≤ 1.5s | 粗糙 8 帧 / 缓存命中 ≤ 200ms |
| 桌面解码 | 总像素 ≤ 5.2M | 见 01 §3 |
| 桌面帧翻转 | 由 launcher 承担，App 进程零参与 | 保持 `ViewFlipper` 自翻，不要改回"App 主动推帧"（那条路已证明被节流） |
| 重烘焙频率 | ≤ 4 次/天（时间档）+ 天气变化 | 其余全部命中缓存 |

**流式烘焙的接口改动**（这是本方案里最容易做错的一处）：

```kotlin
// 现在：一次返回全部帧，调用方再落盘
fun frameFiles(...): List<File>?

// 改成：边烘边落，回调进度
fun bakeAsync(
    ctx: Context, spec: String, wPx: Int, hPx: Int,
    onProgress: (done: Int, total: Int, preview: File?) -> Unit,
    onDone: (files: List<File>) -> Unit,
)
```

## 9. 常见坑（按踩坑代价排序）

1. **改了帧数但没改 `existingFiles()`**：它硬编码 `(0 until FRAMES)`，而 `FRAMES` 现在是编译期常数。改帧数后索引越界或读到空文件 → 桌面显示空白，且**不报错**。必须先从 meta 读帧数。
2. **缓存 key 没有内核版本**：换代后用户永远看到旧帧（`meta` 里的 stamp 一模一样）。
3. **`recycle()` 与 `LruCache` 冲突**：现有 `ArtRepo` 有 `LruCache<String, Bitmap>` 缓存缩略图，如果烘焙路径复用了同一批 Bitmap 又 recycle，会抛 `Canvas: trying to use a recycled bitmap`。流式烘焙的 Bitmap **不进任何缓存**。
4. **`ViewFlipper` 在 launcher 被回收重建后从 f0 开始**：这是正常的，不要试图持久化播放位置（`RemoteViews` 没法控制）。
5. **24 个 layout 漏改一个**：用字体变体的用户会看到"别的都 200ms、就我这套 250ms"。必须用单测遍历 `res/layout/widget_today_f_*.xml` 校验。
6. **PNG 体积暴涨**：40 帧 × 480×270 的雾状渐变 PNG 可能每张 300KB（噪点会让 PNG 几乎压不动）。加了颗粒之后**必须重测体积**，超 6MB 就把颗粒强度降到 1.2% 或改用 WebP。这是个真实的陷阱，别到最后才发现。
7. **圆角必须画在帧里**：`RemoteViews` 没有圆角属性，`WidgetArt.rounded()` 这一步不能省，半径用 16dp × scale，和静态主题保持一致（否则"有的方有的圆"，3.4.53 修过一次）。
