# 06 · 任务清单与排期

## 1. PR 拆分（一次只做一个，做完停下等验收）

### P0 — 骨架与版本化（半天，风险最低，必须先做）

| 改什么 | 文件 |
| --- | --- |
| `meta.json` 替代 stamp 字符串；缓存目录 `wframes` → `wframes2` | `WidgetFrames.kt` |
| `existingFiles()` 从 meta 读帧数（去掉硬编码 `0 until FRAMES`） | `WidgetFrames.kt` |
| 流式烘焙接口 `bakeAsync(...)`，逐帧落盘即释放 | `WidgetFrames.kt` |
| 参数表：`framesOf(spec)` / `stepOf(spec)`，暂只返回现值（24 / 0.25） | `WidgetFrames.kt` |
| 24 个 layout 的 `flipInterval` 与 anim 引用批量脚本化改动 + 校验单测 | `res/layout/*`、`app/src/test` |

**验收**：`check_frames.py` 对现有 24 帧产物 PASS；24 款字体变体在真机全部正常；`./gradlew :app:testDebugUnitTest --offline` 全绿。
**回滚**：只依赖这一个 PR 的 `bakeAsync` 签名，回滚即恢复旧版，无数据迁移。

### P1 — 渲染内核 + 3 款样张（2~3 天，决定画质天花板）

| 改什么 | 文件 |
| --- | --- |
| EGL/GLES3 离屏渲染 + 编译缓存 + 失败自检 | 新增 `widget/shader/GlProgram.kt` |
| 3 款主题的 GLSL 与参数（`liquid` / `dusk` / `dune`） | 新增 `widget/shader/ShaderPresets.kt` |

**验收**：3 款样张的真机截图 + `check_frames.py` 报告 + 盲测第一轮（§05.4，只需过 60% 判定"方向对不对"）。
**回滚**：`shader_ok=false` 即全量回退经典款（这个开关在 P1 就要做出来）。

## 3. 风险表

| 风险 | 概率 | 影响 | 应对 |
| --- | --- | --- | --- |
| 部分国产 ROM 的 EGL pbuffer 创建失败 | 中 | 新图库对该机不可用 | 开机自检 + 全量回退经典款（P1 就做） |
| 加颗粒后 PNG 体积超 6MB | 高 | 桌面内存告警、被回收 | 先测体积再定稿件；不行降颗粒到 1.2% 或改 WebP |
| 40 帧在低端机烘焙超时 | 中 | 用户等太久 | 渐进式烘焙（P2）+ 后台任务取消策略 |
| MIUI 桌面回收组件 | 中 | 用户以为坏了 | 总像素 ≤ 5.2M；24h 挂机验收（§05.3 第 4 项） |
| 24 个 layout 漏改 | 高 | 部分字体变体表现不一致 | 单测遍历校验（P0） |
| 老用户主题被"静默换掉" | 中 | 信任损失 | 只提示不替换（03 §4） |
| GLSL 写不出壁纸级画质 | 中 | 整个方案白做 | P1 就做盲测，方向不对立刻停，改走"高质量静图 + Ken Burns"（成本低一档） |

**止损点**：P1 结束的盲测如果 < 60%，不要继续投 P2/P3，改走备选路线（高质量摄影/AI 图 + 慢速推拉 + 颗粒暗角，全 Canvas 实现）。这条备选路线不依赖 GL，风险低，观感也能到"像壁纸"，只是没有流体那种动态。
