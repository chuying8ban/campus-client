# 参考与边界

这份文件回答一件事：这个仓库里的东西是从哪里来的，哪些是通用工程手法，哪些做法不能碰。写它不是为了免责，是为了让读到代码的人能自己判断。

## 这不是哪个开源项目的复刻

客户端是为一个已经在用的工具新写的一侧：同一作者的网页版（Python / FastAPI，不在本仓库内）先有，Android 这一侧后写。因此代码里会出现大量「与网页版同一口径」的说法——那指的是**同一作者的另一半实现**，不是别人的项目。

## 读过 / 对照过什么

| 对象 | 关系 | 边界 |
| --- | --- | --- |
| 同作者的网页版（FastAPI + 前端页面） | 同一产品的另一半，本仓库网络请求指向它 | 规则口径（周次换算、streak 语义、资源目录结构）以它为准，两边不一致时测试会红。可以复用：数据契约、接口路径、纯逻辑的判定规则。**它的服务端目录树不在本仓库内，也不是本仓库的参考实现**——想动那一半得单独走一遍清理 |
| TWA（Trusted Web Activity）打包方案 | 早期用它把网页版装进安卓壳，后来改原生 | 只借用「打包与签名分离」这个思路：包名与网页版不同、本来就不能互相升级，所以不复用它的 keystore |
| 目标教务系统（`eams.cupk.edu.cn`） | 数据来源，非参考实现 | 只读调用其公开登录与查询流程，读当前用户自己的数据；不复制其前端资源 |

## 通用做法 vs 雷同边界

可以照着写的（公开、通用，任何 Android 项目都这么干）：Compose + Room + kotlinx.serialization 的分层，Repository/UseCase 的切法，Robolectric + Compose 冒烟测试的搭法，Gradle 里把敏感值赶进 `local.properties` 与环境变量的写法。

不要做的：把同类开源课表 App 的界面结构、文案、状态词、接口信封形态照搬过来。本项目页面文案与状态词源自网页版自己的词表，接口是小写扁平 JSON，和常见同类项目的信封式响应不同——这一点谁都能自己比对。

## 演示数据

`app/src/main/assets/` 与 `app/src/test/resources/` 里的课程、教师、院系、资源条目均为合成或占位：人名是「教师一…教师十二」「讲师甲」这类虚构称呼，任务文本是「演示条目NNN：…」，校名用「示例大学（北京）示例市校区」。

唯一出现的真实名称是公开信息：演示资源标题里引用了中国大学MOOC 等平台上的公开课程及其来源高校，用来让目录看起来可信。这些不是本机构的课程数据，也不构成对相关平台的任何关联。

## 美术与素材

界面里的内置背景图是**程序生成的矢量渐变**（本项目原创：程序化生成 + 人工校对），不含任何第三方图片或字体素材——MIT 只覆盖本仓库的代码，往里塞来源不明的素材就是把版权问题带进公开仓。**不写"自绘"这种说法**：程序生成的如实写程序生成。

用户自己挑的背景图只落在本机 App 目录（`filesDir`），不上传；那条路径走系统照片选择器，所以不申请存储权限。若将来要放真实照片进包，必须同时满足两条：来源与许可可转授、且算进 APK 体积预算——并在本节写明来源。
