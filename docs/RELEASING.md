# 发版须知

给以后维护它的人（很可能就是几个月后的你）。发一次新版要做的事一次列清，漏掉哪一步、后果是什么都写在旁边。

**本文件只讲公开这条线。** 这个项目还有一条作者自用的私有通道（作者版包 + 它自己的更新清单），机制不写在这里，见仓外的运维手册；改那条线之前先读那份手册。

## 一次发版 = 三条公开通道同时更新

| 通道 | 给谁 | 做什么 |
| --- | --- | --- |
| GitHub Release | 新用户下载 | 上传 `campus-<版本>.apk`，写清安装步骤、非官方声明、抢课免责 |
| 服务端 `/updates/manifest.json` + 同目录下的包 | 已装用户（App 内「我的 → 检查更新」） | 换 manifest 的 `version_code` / `version_name` / `url` / `sha256` / `size`，并把新包放到 `url` 指的位置 |
| 服务端 `/updates/latest.apk` 稳定别名（软链） | 下载页 / 拿不到清单时的兜底 | 重新指向新包 |

**一次发版要同时换这三处**：新包、manifest 的版本号+sha256+size、`latest.apk` 软链。漏前两处，已装用户看不到更新提示；漏 `latest.apk`，走下载页的人拿到旧包（`/var/www/study-dl/index.html` 的按钮主链接与 JS 兜底都指它）。

只做 GitHub：老用户永远收不到提示。只做服务端：新用户找不到下载入口。**旧包在服务端留着**，老用户才不会断。

**每次发版都要在 App 内可见**：换 manifest 版本号不是可选项——不换，用户在新版发布后打开 App 只看得到"已是最新"。

## 版本号

- `versionCode` **只增不减**：更新判定是「清单里的号 > 当前装的号」，号不涨的包在用户设备上不会被视为更新（静默不动，界面上也看不出问题）。
- 同一个 `applicationId` 才能覆盖安装；换包名等于另起一个 App，用户的本地数据不会跟过去。
- 若同一个仓库里还维护着别的构建线（作者自用那条），它的号必须**永远高于**公开包——号低的那条会被高的那条在它自己设备上"更新"掉。细节见仓外手册。

## 签名

- 所有对外发布的包用**同一把 keystore**（证书 SHA-256 前 8 位 `6eb42692`）。换钥匙意味着已装用户必须先卸载，本地数据一起丢。
- 口令只放受控文件（本机 `local.properties` 或 `~/.config/` 下的 600 文件）：**不进仓库、不进命令行参数、不进聊天**，构建脚本从文件或环境变量读。
- 每次打包后必核：`apksigner verify --print-certs` 的证书 SHA-256 **逐字符等于基准**，不等就停、不上传。

## 发版顺序

1. 改代码 → 跑**全部单元测试** → 文档与代码**同一个 commit**（文档不进 APK，但仍在最终 HEAD 上记一次指纹）。
2. 打包（`-PapiBase=…`）。
3. 验签等于基准证书；跑产物侧断言：「内部口气 / 假声明」那几串 **0 命中**；后台那一族**允许命中**（实现随包、入口由构建开关关掉）——别把它报成 0 命中，那是假判据。
4. 把包放上服务端、换 manifest（三处一起）。
5. 建 GitHub Release：正文**只放发布内容**（别把维护者说明、占位符提示那份草稿直接当 `--notes-file` 发出去，它会被原样公开）；附上 sha256、大小、签名证书前 8 位。
6. 回读校验：Release 附件能下载且 sha256 与打包件一致；manifest 的版本号与包一致；已装用户点「检查更新」能看到新版本。

**构建纪律**

- **构建机 = 本机 Mac**（JDK 17 + Android SDK；`local.properties` 的 `sdk.dir` 必须指本机，别留别的机器的路径——那个错会让构建当场失败，而报错看着像环境问题）。
- **依赖取件**：Robolectric 的 `android-all` jar 在这台机器上走本机离线目录（`~/.config/study-native/robolectric-deps/`）——写法是**条件式**：目录存在才打开 `robolectric.offline=true` 并把 `dependency.dir` 指过去，否则照旧走仓里配的 aliyun 镜像。**别把 `offline=true` 写死**，那会让没预置的机器、或升完版本的新包直接构建失败。升 Robolectric 版本时要往那个目录再放一个对应版本的 jar（文件名绑版本号）。
- **换构建机后，产物的 `sha256` 必须重取**（构建不是逐字节可复现）；**源码指纹与签名证书指纹与机器无关**，不用重算。
- 发布完把临时产物（解出的包、日志、中间目录、临时 keystore）清掉，别留在别的机器上。

## 服务端

- 已装用户的更新提示来自 `/updates/manifest.json`，包放同一目录；该目录不列目录（403）、不存在的文件 404。
- 每天那次课表同步按学号**错峰**在 06:00–08:00 之间跑，另有并发闸门。错峰不是优化而是保护：同一个 IP 连着登多个账号很容易被教务判成异常。
- **cron 的最后一拍必须 ≥ 错峰窗口末端**（窗口 06:00–08:00、slot 最晚 07:59，所以尾拍要落在 08:00 或更晚；现用 `*/30 6-8`）。**改窗口就必须重算频率**——最后一拍落进窗口里，尾部那些 slot 永远轮不到。
- **失败也要有退避**：只有成功路径会写 `last_refresh`，失败账号会被每一拍反复重试；同一个 IP 上的失败登录比成功登录更容易触发风控。频率调细之前先确认失败退避真的生效（走带 `Registry`/`Gate` 的调度路径，而不是只跑一个裸循环）。
- **动这条 cron 之前，先确认 `due()` 用的时钟和 `last_refresh` 的写入口径是同一个**（本仓库已知的缺陷：一个用本地时间、一个写 UTC）。口径不一致时判定会天天认为"今天还没刷过"，把频率调细就等于同一个人一早上被重刷几十遍——正是错峰要防的那种形态。
- 跳过日志**把两种相反的状态分开写**（"今天已刷过" / "未到错峰时刻"）：合成一句话的写法已经让一个故障藏了十几天没人发现。
- 动服务端先备份（DB 用 `conn.backup()`，WAL 下别 `cp`），改完回读验证。

## 更新通道的隐私隔离（发布前必核）

更新是**匿名**的：服务端不需要知道"是谁在更新"，也不该知道。发布前逐条核过，缺一条就是一句站不住的隐私声明：

- [ ] manifest 与 APK 两条 URL **不带 token、不带学号、不带任何用户标识**；不要加 `uid` 之类的查询参数，也不要按用户区分路径。
- [ ] 客户端请求更新时**不附带登录令牌或账号字段**：版本检查发的是空 header + `token = null`，APK 下载那条连 header 参数都不存在。检查 URL 上那个 `?t=<毫秒>` 是**防缓存**用的，**别以隐私为名删掉**——删了用户就再也收不到更新提示；它只含毫秒时间、不含身份。
- [ ] 服务端侧：`/updates/*` 是 nginx 直发的静态目录，应用不参与；访问日志是默认 combined 格式，字段为 **IP / 时间 / 方法+URL+协议 / 状态 / 字节数 / referer / UA**，不含 uid、不含令牌、不按用户分路径。→ 这条声明的边界是：**来源 IP 与 UA 会被记录**（任何网站都会），所以写文档时写"不知道是谁在更新"，**别写"什么都不记"**。
- [ ] 发布后从公网各取一次 manifest 与 APK，核对 URL 里没有任何用户标识，且没有多出按用户区分的落点。

## 文档

- `README.md` 与 `README_EN.md` 同步改，两版必须说同一件事；发版后回读**渲染后的页面**（语言互链、相对链接、LICENSE 是否被判成 MIT、About 的描述与 topics 是否生效）。
- 隐私与安全类声明只写能在代码或实测里指出来的话；写不了的（"不会写进任何日志"这类绝对句）不要写。
- 版本号、用例数这类会漂的数字不要写死在正文里——要留痕迹就写清它属于哪一次。
- **给发布用的文件只能装发布内容**：维护者说明、占位符提示另放一个文件，否则 `gh release create --notes-file <草稿>` 会把它们原样发到公开页。
- **服务端返回的 `detail` 是直接给同学看的话**：任何一条都**不许包含对用户身份或操作的怀疑**（"可能不是本校账号""密码错了吧"这类是把系统状态压成用户过失），也别说"请联系作者"（作者修不了教务系统）；要写就写清是什么状态、会不会自动重试，别承诺具体时间。这类字符串改动前先在 fixture 上干跑一遍再上线。
