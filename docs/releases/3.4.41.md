# 校园助手 3.4.41 —— 预览、自检、桌面三方对齐

## 你看到的问题
截图里「预览」「自检」两张卡长得不一样：预览只放一行日程，自检多一行还把第二行裁掉半行。桌面上也一样，最后一行被切了一半。

## 三个原因（都不是"观感问题"，是三个假尺寸）
1. **预览写死 2:1**：`aspectRatio(2f)`，而你桌面那一格是 320×161 ≈ 1.99，比例本来就不一样；
2. **自检写死 900×400 像素**，再塞进固定 150dp 高的框里 —— 比例被拉歪，内容超出就被裁；
3. **行数按 launcher 报的尺寸算，报的数比实际给的大**：我用 Robolectric 真的 inflate + measure 了一遍 `widget_today.xml`：
   - 只画状态+课名 **99.7dp**
   - 加 1 行 **120.3dp**
   - 2 行 **139.0dp**
   - 3 行 **157.7dp**
   
   MIUI 4×2 报 `MIN_HEIGHT=161dp`，按 2 行去画（需要 139dp），实际可用高度在一百二十出头 → 最后一行必然被切。

## 改法
- 新增 `TodayWidgetProvider.deskSizeDp()`：读桌面上真实实例的宽高（没有实例时用典型 4×2 = 320×161dp）。**预览、自检都用它**，比例跟着它走（不再写死 2:1 / 900×400 / 150dp）。
- 新增 `HEIGHT_SAFETY_DP = 18dp`：算行数前先从报来的高度里扣掉，宁可少放一行，不把一行切成两半。
- 预览的行数也用同一个 `rowsFor(usableHDp(h))`，不再永远画 3 行。
- 自检那张卡的高度改成 `aspectRatio(真实宽/真实高)`，内容不会被拉歪。

## 守这件事的用例
`WidgetRowFitTest`：真的 inflate 布局、真的 measure，对 80~280dp 每个高度断言"`rowsFor` 要求的行数一定放得下"，另加"161dp 那档必须 1~2 行、100dp 不许画行、兜底尺寸自洽"。以后改字号/间距/行高，这个用例会先红，不用等你在桌面上看到半行。
