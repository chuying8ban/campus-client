# 校园助手 3.4.20

## 「静止时总是不显示，点微动就有了」

这句话本身就是线索：同一张图，**换个选项一个能看一个不能**，说明不是图坏了，是两条路走的不一样。

- 微动 → `WidgetFrames` 取帧 → 3.4.18 已经加了 `ImgLift` 提亮；
- 静止 → `WidgetThemes.imageBitmap` → `bgBitmap` → **这条路漏了提亮**。

你那张"我的图"实测平均亮度 39/255（中心 #031A56，深藏青），再压一层 40%~60% 黑遮罩，
在 OLED 上就是纯黑。所以自检里的预览和桌面那张卡都是黑的，而同样的图一动起来就出来了。

三处改动：

1. `imageBitmap` 走 `ImgLift`（和帧分支一致）。老图不用重传。
2. 遮罩 `0x66/0x99`（40%→60% 黑）→ `0x33/0x66`（20%→40%）。文字本来就有底色衬着，用不着压这么狠，
   40% 的起始黑已经足够吃掉照片的杂乱。
3. `BG_MAX_PX` 60k → 90k：你那块 320×161dp 的卡，60k 只够 367×163，拉到 960px 宽是 2.6 倍放大，
   发虚。90k 约等于 450×200，清晰度好一档，离 binder 上限也还远。

`ImgLift` 也改成直接改像素（`getPixels`/`setPixels`），不再用 `Canvas + ColorMatrixColorFilter`：
后者在单测环境里画出来是全黑，改完就分不清"图真黑"还是"环境不支持"。

## 测试

新增 `WidgetDarkImageTest`：暗图必须被抬到 >45，本来就亮的图必须原样返回（`assertSame`），提亮不许动 alpha。
图形全部用 `setPixels` 造 —— Robolectric 的 `Canvas.drawColor` 和 `BitmapFactory.decodeFile` 都不真的落像素。
