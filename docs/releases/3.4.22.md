# 校园助手 3.4.22

## 「静止时总是不显示」的真正原因

`TodayWidgetProvider.applyTheme` 里写的是：

```kotlin
if (dyn == null) { …画底图… }
```

`dyn` 是 **Boolean**，`dyn == null` 恒为 false。所以**静态分支一次都没执行过** ——
纯色、随包图片、我的图，全都没有底图，只剩深色底 + 文字。而"微动/动态"走的是上面
`WidgetFrames` 那条路，一直正常。于是表现成"静止什么都没有，一点动效就有了"。

改成 `if (!dyn)`。这一条同时解释了 3.4.20 之前所有"图片主题是黑的"的截图。

## 「客户端主题和小控件主题串了」

代码里两边是**各写各的**：App 那排动效写 `AppearanceStore`（`animphoto:`），小组件那排写
`WidgetThemes`（`dyni:`），没有任何一处互相写。真正的问题是**两页各有一排长得一模一样的芯片**
（都叫「动效」），点错了一整屏就变。现在标题写死作用范围：

- App 页：「动效（只影响 App 背景，不动桌面小组件）」
- 小组件页：「动效（只影响桌面小组件，不动 App 背景）」

## 切换主题不够实时

`refresh()` 原来先 `warmFrames`（解码 4 帧）再推给桌面，动态主题要等 1~2 秒。
现在**先推一版**（静态主题几百毫秒就变），再预热帧、推第二版（动态更稳）。

## 动态主题流畅度

App 的动效原来是 `while(true){ t=…; delay(33) }` —— 固定 30fps 的死循环，跟屏幕刷新不同步，
所以看起来"一顿一顿"。改成 `withFrameNanos`：跟着 vsync 走，60Hz 上就是 60fps，
掉帧时自动少画一帧、不会越拖越远。`t` 只在 `Canvas` 的 draw lambda 里被读，只触发重绘不重组整棵树。
