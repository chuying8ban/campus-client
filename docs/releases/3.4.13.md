# 校园助手 3.4.13

## 为什么又让你输账号密码

之前的「自动登录」**不是免密登录**，它保住的是**登录会话**：登录成功后把学校发的
`SESSION` / `__pstsid__` 改写成带过期时间的持久 Cookie，App 重启后还能用。

问题在于会话是**学校那边**发的，树维 EAMS 会按它自己的策略让会话失效（闲置一段时间、
或者换网络、或者服务端重启）。会话一失效，客户端手里就只剩一张过期的票，
没有任何办法凭空续上 —— 只能重新登录。这不是 App 的 bug，是"不存密码"这个选择必然的代价。

## 这版给的解法：可选「记住账号密码」

导入页「登录一次，以后进入自动登录」下面新增一行：

> ☐ 账号密码也记住（自动登录）

勾上 → 填一次学号 + 密码 → 保存后：

- 用 **Android Keystore** 里的 AES/GCM 密钥加密（硬件支持时密钥不出安全芯片），
  本机只留密文，App 里没有明文密码；
- 学校登录页一出现，自动**填好用户名密码并点登录**，你基本看不到这个页面；
- 关闭这个勾 → 连密文一起删；卸载/清数据也一起消失；不上传、不参与云同步。

默认**仍然是关的**，行为和以前完全一样（只保留会话、不存密码）。共用手机别开。

## 实现要点

- 写值用 `HTMLInputElement.prototype` 的原生 setter 再派发 `input` 事件 —— 直接
  `el.value = x` 不会触发 Vue 双向绑定，点登录时提交的还是空串，这是这类自动填表最常见的坑。
- 登录页是 Vue 异步渲染的，表单出现有延迟 → 错开 1.2s / 3s / 6.5s 重试三次，
  已经跳走就不再注入。
- 输入框按 `placeholder`（用户名/账号/学号、密码）找，树维这套页面没有稳定的 id。
- 原有的安全边界没动：不开 `addJavascriptInterface`、不读学校页面里的密码 DOM、
  强制 same-origin、导入结束清登录状态。`CrawlScreenTest` 从"禁止一切密码框"
  改成"只允许勾选入口那个文件出现密码框，其余照旧禁止"。
